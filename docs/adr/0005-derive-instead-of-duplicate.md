# 0005 能推导的状态不重复存储

- **Status**: Accepted
- **对应宪法条款**: C5

## 决策

能可靠地从其他事实推导的字段，用纯函数推导，不维护第二份可变状态。

只有四种情况允许冗余：明确的查询性能需要、持久化当时的历史快照、跨进程协议需要、
以及已文档记录且定义了更新者与修复策略的。

Eva 里的判例：

- 会话展示状态（running / requires_action / idle）**推导**自在跑的 Run、待审批请求、活跃后台任务；
- SSE 是投影，不是 Run 状态事实源；
- `messages.search_text` 是可重建索引投影；
- Run 当时用的模型与 capture level 是**历史快照**，要持久化；
- Plan Weave 的 `ready` 不是持久字段，每次按 deps 重算 —— 所以手改 `plan.json` 能自愈。

## 为什么

第二份可变状态的维护费是「每一个写入点都要记得同步」，而漏掉一个的表现是数据不一致，
不是报错。

## 代价

每次读要多算一点。Eva 的规模下这个成本可以忽略（推导都在本地 SQLite 与内存里）。

## 什么情况下推翻

某个推导出现在热路径且实测成为瓶颈 —— 那时按上面四条之一记录下来，并写明谁负责更新、
不一致时怎么修。

## 怎么验证

`tests/server/sessions/session-status.test.ts` 一类的推导测试；review 时问「这个字段能不能算出来」。
